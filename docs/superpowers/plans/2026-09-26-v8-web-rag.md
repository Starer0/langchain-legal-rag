# V8.1 Web RAG MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deployable FastAPI legal-RAG chat page with isolated anonymous sessions, SQLite-backed history, and streamed final answers.

**Architecture:** Keep the existing CLI chain unchanged. Add a reusable streaming RAG turn service that receives explicit history, emits typed stage events, and uses the existing Rewrite → Chroma → Reranker pipeline before streaming the final model output. FastAPI owns cookies, SQLite persistence, SSE encoding, and static assets; it writes a complete turn only after a `done` event.

**Tech Stack:** Python 3, FastAPI, Uvicorn, SQLite standard library, LangChain/OpenAI-compatible model client, Chroma, HTML, CSS, browser Fetch API.

**Spec:** `docs/superpowers/specs/2026-09-26-v8-web-rag-design.md`

## Global Constraints

- Retain `main.py` as the CLI entry point and preserve all V1–V8 CLI behavior.
- Web defaults to the single-query V6 pipeline; it never implicitly enables `--decompose`.
- Cookie stores only a high-entropy anonymous session ID; API keys and message content stay server-side.
- Use `HttpOnly`, `SameSite=Lax`, and configurable `Secure` cookie behavior.
- SQLite writes one user/assistant pair only after a complete successful answer; error, cancellation, and stream failure save no partial pair.
- History-aware Rewrite receives only the newest `HISTORY_TURNS` complete pairs.
- SSE order is `status*`, `delta*`, then exactly one terminal `done` or `error`.
- Do not log raw question text, answer text, cookie values, or API keys.
- Ignore `.superpowers/`, `data/web_rag.sqlite3`, `.env`, vector stores, and generated evaluation results.
- Use `python -m unittest discover -s tests -v`; new behavior is test-first and each task has a separate Git commit.

```python
class SQLiteConversationStore:
    def ensure_session(self, session_id):
        session_id = session_id or secrets.token_urlsafe(32)
        with self._connection() as connection:
            connection.execute(
                "INSERT OR IGNORE INTO sessions(id, created_at, last_seen_at) VALUES (?, ?, ?)",
                (session_id, now, now),
            )
        return session_id

    def save_complete_turn(self, session_id, question, answer):
        if not question.strip() or not answer.strip():
            raise ValueError("问题和回答不能为空")
        with self._connection() as connection:
            next_ordinal = self._next_ordinal(connection, session_id)
            connection.executemany(
                "INSERT INTO messages(session_id, ordinal, role, content, created_at) VALUES (?, ?, ?, ?, ?)",
                [(session_id, next_ordinal, "user", question, now),
                 (session_id, next_ordinal + 1, "assistant", answer, now)],
            )
```

Create `sessions` and `messages` with `CREATE TABLE IF NOT EXISTS`; use a new SQLite connection per repository operation. Add `data/web_rag.sqlite3` to `.gitignore`. Add a concise `requirements.txt` that declares the existing RAG packages plus `fastapi` and `uvicorn[standard]` without embedding local `.venv` paths.

```python
def stream(self, question, messages):
    history = recent_complete_turns(messages, self.history_turns)
    yield {"event": "status", "data": {"stage": "rewrite"}}
    retrieval_question = self.rewriter.rewrite(question, history)
    state = {"question": question, "retrieval_question": retrieval_question}
    yield {"event": "status", "data": {"stage": "retrieve"}}
    candidates = self.retriever.invoke(state)
    yield {"event": "status", "data": {"stage": "rerank"}}
    docs = self.reranker.invoke({**state, "candidates": candidates})
    yield {"event": "status", "data": {"stage": "answer"}}
    answer_parts = []
    for chunk in self.model.stream(self.prompt.invoke({"context": format_docs(docs), "question": question})):
        text = _chunk_text(chunk)
        if text:
            answer_parts.append(text)
            yield {"event": "delta", "data": {"text": text}}
    yield {"event": "done", "data": {"answer": "".join(answer_parts), ...}}
```

Use the current answer prompt and `format_sources`. Record performance with the existing `TurnProfile`; include it only in `done`. Raise ordinary exceptions to the API layer instead of converting them into a successful `done` event.

```python
def _sse(event, data):
    return f"event: {event}\\ndata: {json.dumps(data, ensure_ascii=False)}\\n\\n"

@app.post("/api/chat")
def chat(payload: ChatRequest, request: Request):
    session_id, is_new = session_from_request(request)
    def events():
        try:
            messages = to_langchain_messages(store.load_messages(session_id))
            answer = ""
            for item in rag_turn.stream(payload.question.strip(), messages):
                if item["event"] == "delta":
                    answer += item["data"]["text"]
                if item["event"] == "done":
                    store.save_complete_turn(session_id, payload.question.strip(), answer)
                yield _sse(item["event"], item["data"])
        except Exception:
            yield _sse("error", {"message": "暂时无法完成回答，请稍后重试。"})
    response = StreamingResponse(events(), media_type="text/event-stream")
    if is_new:
        response.set_cookie("legal_rag_session", session_id, httponly=True, samesite="lax", secure=secure_cookies)
    return response
```
