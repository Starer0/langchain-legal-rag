# Web Login Implementation Plan

> **For agentic workers:** Execute inline through executing-plans, then a fresh read-only review. User approval covers this login step.

**Goal:** Connect the existing accounts to the existing web UI with mandatory login, logout, three-day sliding sessions and account-owned conversations.

**Architecture:** Explicit additive migration, shared conversation owner implementation, persisted opaque login sessions and pure ASGI auth guard; lightweight auth client integrated with current static page.

**Tech Stack:** PostgreSQL, psycopg2, FastAPI / Starlette, Python unittest, browser JS modules and Node tests.

**Spec:** docs/superpowers/specs/2026-10-03-web-login-design.md

## Constraints

No anonymous record assignment, real retrieval authorization, React or task recovery in this step. Preserve pending V12 changes and local credentials. Product cannot silently fall back to anonymous. Tests write only their UUID schemas. HANDOFF and credentials stay ignored; no auto-commit of pending lessons.
