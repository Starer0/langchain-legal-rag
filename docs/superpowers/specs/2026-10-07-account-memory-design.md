# 网页账号长期记忆：核心与扩展两层设计

日期：2026-10-07。状态：用户已批准并于本地实施。本文保留设计阶段约定，实际验证/部署见docs/v12-15-account-memory.md及本地HANDOFF。

## 目标与已确认方向

借鉴 Letta 公开的核心/归档分层思路，在现有 React、FastAPI、PostgreSQL、LangGraph 项目实现账号长期记忆，不引入 Letta 框架。用户在设置页直接编辑，也可在对话中明确要求记住、修改、忘记。两个入口操作同一份账号记录。

核心记忆为短文本，每次有依据的法律回答都提供；扩展记忆按当前问题选择相关内容。原先“短记忆全部加入、超过总长度阈值后才筛选”的方案被此分层方向替代。初版不自动从普通聊天推断或定期提取记忆，不增加风格预设，不升级现有短期上下文策略。

记忆只能影响背景与表达方式，不能授予资料权限或成为法律依据。案件日期、工资金额、合同条件等默认留在当前对话，初版不支持将这类具体案件资料自动保存为跨对话记忆。

## 内容与用户界面

在现有侧栏账号区增加“记忆设置”入口，打开独立设置面板，不重新设计整个聊天工作区。保留当前配色、字号和移动端布局。两个有标签的文本区域：

1. 核心记忆：说明“每次回答使用”。用于语言、详略、先结论、解释方式、保留引用等，以及用户明确指定的必要稳定背景。
2. 扩展记忆：说明“与问题相关时使用”。用于有主题范围的稳定背景；编辑区支持分段或一条一行，不要求用户填写JSON/标签/向量。

一个“在回答中使用记忆”开关控制两层读取与注入，关闭不删除原文。即使关闭仍可编辑或通过明确指令更新；保存反馈说明当前开关关闭。新账号默认开启、内容为空，此时不产生记忆外部调用。

显式保存，不做每按一次键自动保存。保存中、成功、字段错误、服务失败、版本冲突均有可见反馈；失败/冲突保留草稿，不静默覆盖。清空核心、清空扩展、清空全部是明确操作，破坏性清空需要一次产品内确认。未保存离开时提醒；键盘可达、关闭后恢复焦点、移动端无横向滚动、按钮触控尺寸足够。只按已登录账号加载；切换身份清空草稿与状态，迟到响应不能覆盖新账号。设置面板不干扰后台任务观察。

## 预算与扩展条目

核心初始预算目标500个估算token，并加1500字符硬上限；扩展原文最多12000字符、40条，每条最多1000字符；一次回答最多选择3条扩展，扩展输入目标不超过500个估算token。均为可配置试用参数，不宣称最佳值。实施采用明确命名的本地token估算器；若不是提供商对应tokenizer，界面和记录明确“估算”，不把估算当作实际计费token。字符限制提供确定边界，不依赖有网络的token计数。

核心超限拒绝保存，提示精简或移到扩展区，不静默截断或擅自改写。扩展按明确段落/列表项边界形成辅助条目，保留原始文本；规则整理不引入新事实，不按任意字符切断语义。单条超限提示分段。设置直接保存无需额外聊天模型调用。

条目embedding沿用项目现有embedding服务；向量保存在PostgreSQL，小规模账号条目在应用内比较，不接入Chroma法律索引、pgvector或独立向量服务。这里“本地比较”不等于embedding在本机生成；现有embedding服务仍是远程调用。首次保存/修改扩展只生成需要变更的条目向量，未变更条目在相同模型指纹下复用；指纹包含提供商配置标识、模型与维度，不含密钥。删除/清空不调用embedding。

相关性使用当前原始问题生成的query embedding与当前账号有效条目做cosine比较；先过滤不匹配模型/维度、无效/非有限向量，再按分数、稳定条目顺序排序，应用相关性下限与条数/预算。初始下限0.5仅为可配置待验证起点，不能解释为相关概率或已校准阈值；开发场景检查同义问法命中和无关主题排除，实施前/中据开发集选择值，不用冻结保留题调参。不够相关时允许0条，不能固定凑Top 3。不额外增加聊天模型或Reranker来选择记忆。

扩展保存需要的embedding失败时原文和旧条目都不更新，保留编辑草稿提示失败；避免原文新、检索旧。查询embedding设置有界超时，失败只降级跳过扩展，不主动增加应用层重试。计划明确实现可支持的超时边界并测试，不能用线程future超时冒充已取消底层请求。

## 数据与接口

新增独立账号记忆存储模块与显式增量迁移，不挤进聊天消息表或图检查点表。采用PostgreSQL JSONB/普通列即可：

- `account_memories`：user_id主键与users外键、enabled、core_text、extended_text、revision、updated_at。空记录对外revision=0；首次保存创建并递增版本，清空保留账号行与递增版本，不能复用旧版本。
- `account_memory_entries`：服务器条目编号、user_id、revision、原文段落位置、text、embedding、embedding指纹，外键归属与唯一约束。
- `generation_memory_inputs`：task_id外键、账号/记忆revision、开关、受限核心与候选扩展快照、处理结果；供当前问答固定输入与恢复检查。随任务/对话删除清理。

`GET /api/memory`返回当前本人原文、开关、版本、更新时间、公开限制；`PUT /api/memory`携带expected_revision与新原文/开关。删除通过显式保存空文本并携带版本处理。请求不能指定他人user_id；验证身份从服务器会话取，所有写入遵守现有CSRF与来源校验。响应no-store，不返回向量、连接信息或其他账号数据。API错误不能回显秘密/不必要私人文本。

保存流程：读取当前版本 → 校验长度/条目 → 必要embedding（数据库事务外，设超时）→ 短事务锁本人行并再次校验版本/账号启用 → 同事务替换原文与条目/开关、递增版本。跨浏览器或聊天/设置同时修改时，旧版本返回409，提示重新加载再编辑，不自动用旧文本覆盖。数据库整体不可用时按已有登录/保存失败规则处理，不能保证跳过记忆后问答仍可用。

## 对话修改：明确意图与保存结果

通过已有聊天提交与后台任务完成操作，便于刷新观察与重启恢复；不把自然语言直接当作授权SQL。程序先保守识别直接面向助手的长期记忆命令候选，普通法律问题不额外调用记忆处理聊天模型。命中候选后用一次受约束的模型解析：操作、目标层、用户明确指定内容、基于旧记录的候选新文本。引用“记住”作讨论、文档内容、临时“这次”要求不能执行长期写入；候选分类不确定时返回澄清，不猜着存。

通用偏好默认核心，主题背景默认扩展；用户明确指定层时优先遵从。修改替换对应项，保留其他项；忘记只移除指明项。无法唯一确定目标、超限、具体案件内容不适合初版、输出无效，返回具体澄清/错误，不变更存储。第一版复合消息同时要求改记忆和回答法律问题时，先提示拆为两条，不隐式决定先后或执行一半。

图中的记忆命令节点只产出候选操作，不写数据库，不发“已记住”成功delta；问答节点不同时运行。最终由后台完成事务再次核验账号/对话/代次/expected_revision，原文与辅助向量准备成功后，同事务写入记忆、聊天反馈、任务completed。模型proposal不能作为已经保存的确认。恢复从已保存proposal继续，完成事务只执行一次；已completed提交重放仅返回原任务，不再改记忆。revision冲突或存储/embedding失败不得落入旧proposal自动重试，不标成功，旧记录保持完整。

命令图版本和完成结果须包含受限、可验证的操作信息；状态/HTTP只交付安全提示，不把proposal内部状态、用户全部记忆或embedding发到聊天API。来源为空，记忆反馈不能伪装法律引用。图完成但事务未提交恢复时，仍重新校验版本；已完成任务不再重写偏好。

## 普通问答的读取与恢复

在任务接受时固定该账号记忆版本与受限输入快照，之后设置修改影响下一项任务，当前执行沿用启动版本。关闭使用时不加载私人内容/不调用记忆embedding；开关开启但扩展为空只使用核心；核心/扩展均空不增加记忆外部调用。

普通问答保持rewrite → retrieve → rerank；有依据后进入新增memory读取/选择节点，再answer。no_evidence直接使用原拒答，不从记忆补造法律依据。记忆不送问题改写、法律召回或重排服务，不改变历史裁剪；只在回答提示中分为“用户背景与表达偏好”区，并保持系统法律依据/权限规则优先。共享CLI/旧顺序执行器不自动获得账号记忆。

检查点保存选中条目、实际注入文本和版本的受限快照，使未完成回答恢复沿用原选择，避免每次接管重做query embedding。运行时MemoryStore/模型/连接/logger与用户身份验证函数放GraphRuntime，不序列化到State。无快照/未开始选择时可重做未完成步骤，与现有节点恢复规则一致。

设置修改不取消正常运行中的回答。服务重启时若当前记忆revision/开关与任务快照不同，尚未完成图的任务安全中断并提示重发，不重新使用被删旧记忆，不把新旧偏好拼接；图已完成只补保存既有回答，不重新注入记忆。这个边界需明确向用户说明。图版本递增，旧版本running任务不强行映射到新图；部署前确认没有运行任务，按已有权限/版本保护处理。

记忆设置删除的是当前记忆与辅助向量，不自动删除过去回答中的内容。任务输入/检查点属于历史执行记录，随对话删除使用既有清理队列清除；备份中的副本沿既有备份规则保留，不声称一次清空等于所有历史/备份物理擦除。不得把这些旧副本作为新任务记忆来源。

## 降级、显示与日志

扩展检索/embedding不可用时，使用已成功取得的核心，继续有依据回答；页面显示“本次未使用扩展记忆”。核心读失败时允许在身份、资料权限与任务/聊天数据库仍可用的前提下跳过全部记忆并提示；数据库整体故障仍按现有错误路径处理。保存失败明确“保存失败”，不继续显示虚假成功反馈。

当前task快照与done结果增加受限memory状态/警告及采用revision，恢复刷新显示一致；不把警告混入模型回答正文或法律sources。普通日志仅记账号/任务/request_id、版本、选中条目ID、数量、长度估算、耗时、跳过/失败原因、调用次数，白名单不含完整私人记忆或向量。日志有状态不代表记忆写入已完成，以事务完成事件确认。

## 验证与量化证据

- 单元与真实临时PG：账号隔离、CSRF、空/超限、版本冲突、未变更向量复用、删除不再选中、保存失败全回滚、无效向量/维度/模型过滤、当前账号选择、开关关闭无memory调用。
- 记忆命令：明确新增/局部修改/忘记、临时要求与引用文字不误存、模糊目标澄清、案件条件不自动跨对话、混合指令说明、模型格式错误、重放与恢复副作用一次、冲突不覆盖。
- 问答图：核心恒定提供、相关背景/同义问法命中、无关主题不凑数、实际预算、无依据仍拒答、权限不变、记忆不流入法律检索或sources、检索失败降级可见；answer重做时记忆选择不重复。
- 恢复：proposal完成后/记忆完成事务前强制结束，重开后保存一次；事务提交后重放不变更；设置变更后重启中断未完成旧任务；普通刷新保留反馈和任务状态，账号切换拦截迟到内容。
- React与浏览器：设置可查看编辑两层、保存/清空/开关、冲突保留草稿、聊天修改后重新打开设置见新值、1440/375px键盘和布局、后台生成仍可观察；先本地假模型，真实模型验收另记。
- 开发场景记录选择命中/遗漏、输入估算token、实际可获得usage、embedding及整理调用次数/耗时，比较空记忆、核心、两层；足够样本前不声称节省百分比。记忆评测与法律来源/回答质量分开。

## 迁移、实施与范围

实施计划再细化模块命名、每项变更与测试命令。新增memory_storage.py、memory_service.py和显式准备脚本；前端设置单独组件/controller，避免继续堆进useChat大函数；现有任务完成事务抽取可复用部分，保留普通问答行为。迁移前备份并验证旧表摘要；只新增记忆/任务输入结构，不改已有账号密码或法律索引。未迁移不能在请求时自动建表。
