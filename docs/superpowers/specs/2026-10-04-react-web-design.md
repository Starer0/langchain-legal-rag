# React 网页改造设计：法律法规问答

状态：设计供用户审阅，尚未建立 React 项目或替换正在运行的网页。

## 目标与范围

把现有 HTML / 手动 DOM 页面迁移为 React 组件，改进企业法律问答的布局与交互，继续复用 FastAPI / PostgreSQL / 资料权限 / RAG / 阶段日志。第一版保留登录、退出、聊天新建 / 切换 / 重命名 / 删除、历史恢复、流式问答、来源展示和请求编号错误提示。

此步不新增管理员、日志查看页面、资料上传、长期记忆、任务恢复或复杂问题拆分。截图右侧桌面宠物不作为站内组件迁移。

## 已核对的问题

- 顶部用大号标题完整显示问题，长问题造成多行巨大标题，挤压阅读区。
- 原 CSS 的聊天项是 flex，标题缺少可靠的收缩边界；截图中长项越过侧栏。新布局每个可收缩层明确 min-width:0，并为文本设置截断。
- 原 message-log 与整页一起增长，输入框跟随页面下移；没有固定聊天工作区和独立消息滚动区域。
- 当前键盘发送处理未判断中文输入法组合状态，Enter 确认候选有误发送风险，迁移时覆盖该交互。
- 切换历史请求需区分加载、失败与空对话。旧页面加载失败时显示欢迎且仍可发送，容易让人误以为旧对话没有历史。
- 历史接口目前只返回 role/content，引用没有持久化；本步不能承诺刷新后恢复来源附件。

## 方案选择

推荐独立 frontend/ 项目，React + TypeScript + Vite，普通 CSS 变量定义统一视觉。开发时让请求保持同源（经开发代理），实际使用时由 FastAPI 提供构建后的静态页面，仍使用 127.0.0.1:8001 和相对 /api 路径。Vite 支持 React / TypeScript 模板与静态构建：[官方指南](https://vite.dev/guide/)。组件与状态按 [React 官方思路](https://react.dev/learn/thinking-in-react) 分解。

另一方案是在旧 DOM 页面中局部插入 React；改动初期较小，但两套状态和界面管理容易互相覆盖，无法一次解决滚动布局。本次采用完整 React 工作区，实施时按模块推进，验收后统一切换。

旧网页源文件保留，React 在独立目录开发 / 预览；构建完成前不替换正式入口。原后端接口行为保持，网页入口和静态资源选择属于需要测试的集成改动。FastAPI 找不到配置要求的构建产物时应明确提示准备步骤，不静默宣称已启用 React。

## 页面设计

视觉采用 ui-ux-pro-max 已检索到的 Minimalism / Swiss 风格：深蓝主色 #1e3a8a、浅灰背景 #f8fafc、白色内容区、克制的金棕强调。中文使用本机系统无衬线字体，不依赖外部字体服务。16px 左右正文、舒适行距、细边框、低强度阴影；标题不沿用大号衬线展示风格。使用统一 SVG 图标、明显焦点和轻微反馈。

### 桌面聊天工作区

- 约 260–280px 左侧栏：产品标识、新建按钮、聊天列表及账号 / 退出区域。列表独立滚动；长名称单行截断，可通过可访问标签 / 提示获取全名。选中项浅蓝底，不把每条聊天都做成大蓝按钮。
- 约 64px 紧凑顶部：当前聊天名最多两行，超长截断；不会随标题拉高整页。
- 消息区占据剩余高度并独立滚动，正文居中且宽度约 760–860px。用户问题为浅蓝气泡，助手正文为白色易读区域；引用条文、列表、代码与长链接不会撑破容器。
- 底部输入区稳定可见，textarea 自动增长到上限后内部滚动，发送按钮有等待状态。处理阶段用一条简洁提示展示，错误与请求编号可见。
- 使用提示收紧为低干扰说明，不反复占据大块屏幕。
- 新对话显示简洁欢迎区和 3 个示例问题，点击示例只填入输入框，不自动调用模型。
- 流式输出时，仅在用户接近底部时跟随滚动；用户上翻阅读不强制拉回底部，可显示“回到最新”按钮。

### 登录页与窄屏

- 登录页沿用品牌色和统一表单样式；桌面可用简洁介绍区与登录卡，小屏单列。字段明确标注、自动填充正常、密码不进入存储或日志，错误靠近表单。
- 小屏侧栏变为可打开 / 关闭的抽屉，选择聊天后收起；键盘可操作、关闭后恢复触发按钮焦点。对话阅读与输入始终优先，不用横向滚动聊天按钮代替导航。
- 按 375 / 768 / 1024 / 1440px 检查布局，以及长标题 / 长消息 / 中文输入法。考虑动态视口、键盘弹出和减少动画设置。

## 状态与接口

组件包括登录页、Workspace、Sidebar、ConversationHeader、MessageList、Message、Sources、Composer、重命名和删除确认对话框。展示由 React 状态驱动，不继续依靠全局 DOM 查询操作工作区。

优先复用经过验证的 createAuthClient（请求中 Cookie / CSRF、401 清空、账号版本、旧请求终止）和安全 Markdown 渲染逻辑，配套适配测试。前端只显示当前用户信息，不自行计算资料权限。

状态区分：检查身份、未登录、加载聊天、就绪、加载历史、生成中、操作失败。历史读取失败可明确重试；没有成功加载当前历史前不发送，避免把失败显示成空聊天。各操作设定同步互斥保护；快速切换会话或账号时旧响应不得覆盖当前内容。

问答继续使用原 SSE status/delta/done/error 协议。出现 HTTP 拒绝、SSE 错误、无 done 的中断时，移除未完成问答并恢复草稿，保留可见请求编号；不新增自动重试。中文输入法 Enter 只确认候选，非组合输入的 Enter 才发送，Shift+Enter 换行。流式生成期间禁止切换 / 删除正在生成的聊天，保持现有操作边界。

Sources 区域只展示后端返回的来源。刷新后的历史目前没有来源附件，此为既有接口边界，不能伪造来源或默认全部数据库历史都带引用。
