# V5 本地 RAG 评测设计（中文说明版）

> 这份文件是英文执行版 `2026-09-15-v5-local-rag-evaluation-design.md` 的中文说明，二者描述同一项 V5 工作。

**目标：** 为劳动法 RAG 系统增加一套可在本地重复运行的评测流程：量化检索与重排效果，记录基于原始资料的答案审查，并在前五道题中陪你逐题理解结果。

## 范围

V5 只评测当前 `data/labor_law.pdf` 这份知识库中的内容。它不提供法律意见，不接入 LangSmith，不改变检索行为，不增加分数阈值，也不额外调用另一个大模型充当自动评委。

初始数据集包含 12 道题，覆盖：有直接答案的问题、同义改写的问题、需要多条法条共同回答的问题、容易被重排错位的问题、资料不支持的问题，以及带有错误前提的问题。

## 每道题保存什么

每个用例保存如下信息：

```json
{
  "id": "overtime-pay",
  "question": "加班工资如何计算？",
  "expected_articles": ["第四十四条"],
  "required_facts": [
    "延长工作时间不低于150%",
    "休息日不能补休不低于200%",
    "法定休假日不低于300%"
  ],
  "answerable": true
}
```

如果某题在资料中没有答案，`expected_articles` 与 `required_facts` 均为空，`answerable` 为 `false`。

评测程序会自动检查：每一条预期法条是否出现在 Chroma 初召回结果（Top K）中，以及是否进入重排后的最终资料（Top N）中。对于资料不支持的问题，它还会检查答案是否包含既有的拒答语句 `资料中没有足够依据`。

## 我怎样审查答案

我会将每一次生成的答案与用例中保存的预期依据、以及 `data/labor_law.pdf` 中对应法条原文进行比对。审查只判断答案是否忠实、完整地依据这份 PDF，不判断 PDF 之外的真实法律问题。

每个结果会得到以下一种结论：

- `complete`：答案覆盖全部必要事实，且没有资料不支持的结论。
- `partial`：核心结论有依据，但缺少至少一个必要事实，或表达存在重要不清楚之处。
- `incorrect`：答案与 PDF 矛盾、使用了资料外内容，或对本应能回答的问题错误拒答。
- `correct_refusal`：对资料不支持的问题正确拒答，且没有编造规则。
- `incorrect_refusal`：PDF 中明明有预期法条，答案却错误地拒答。

每条审查记录都会保存结论、支持该结论的法条编号，以及简短的、可追溯到资料的解释。

## 技术结构

现有终端问答入口与评测程序必须共用同一套 RAG 创建逻辑。`main.py` 中的初始化代码会移入一个小型工厂模块，对外提供 `create_rag_chain()`；`main.py` 保持为终端交互入口并导入这个工厂，评测程序也导入同一个工厂。这样环境配置、Chroma 检索、Reranker 重排和 Prompt 格式都会完全一致，评测的就是你实际使用的系统。

新增组件：

```text
rag_app.py
  共享的 create_rag_chain() 工厂。

evals/cases.json
  纳入 Git 管理、包含 12 道题的资料依据型评测集。

evaluate.py
  使用真实的共享 RAG 链路运行指定题目，记录检索指标、答案、配置、候选资料与重排后资料。

evals/results/<run_id>/<case_id>.json
  不可变的原始运行结果，以及我的资料依据型审查。

evals/results/<run_id>/summary.json
  一次完整运行的汇总指标与审查结论统计。
```

评测程序不得把 API Key、完整 PDF 文本或无关环境变量写入结果文件。它只记录：题目数据、法条编号、页码、资料摘要、分数、模型答案、评测配置、时间戳和审查结果。

## 你的使用流程

1. 依次运行第 1 至第 5 题。
2. 每题结束后，向你展示答案、Top K 初召回、Top N 重排结果，以及我基于资料作出的审查。
3. 你可以随时提问或指出疑虑；不需要懂法律，也不需要打分。
4. 如果前五题没有需要讨论的问题，第 6 至第 12 题会连续运行、完成审查并生成汇总。
5. 这份汇总将成为 V5 的基线，供未来改动检索策略后比较。

## 测试策略

单元测试将注入假的 RAG 链路结果，绝不调用 Chroma、聊天模型或 Reranker API。测试范围包括：预期法条命中计算、拒答识别、结果序列化时不泄露密钥、审查结论汇总，以及共享工厂模块的接口。现有 Reranker 测试必须继续通过。

## 完成标准

- 单道题可通过和 `main.py` 相同的链路完成评测。
- 每条结果都标明预期法条是否进入候选资料与最终资料。
- 每条结果保存足以审计审查结论的来源 metadata。
- 前五题可在对话中逐题学习，后七题可在无人干预时完成。
- 最终汇总提供 Top K / Top N 命中率、拒答结果和答案审查结论统计。
