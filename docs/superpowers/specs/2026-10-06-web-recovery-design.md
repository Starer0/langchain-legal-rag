# 网页问答检查点与服务重启恢复设计

## 目标与用户行为

用户已要求开始补齐后端重启后的问答恢复。本方案将持久化图进度与服务器启动接管放在同一小版本中实现。网页刷新续答保持原行为；后端重启后，同一任务、问题与对话自动继续，不要求用户重新提交。回答节点未完成时重新执行该节点，替换旧部分回答，不拼接两次模型生成内容。图完成且检查点保存后、聊天事务提交前重启，应从完成检查点保存结果，不再次调用模型。已经 completed 的任务不再次执行。

## 方案选择

1. 推荐：使用官方 PostgreSQL checkpointer，复用现有 PostgreSQL，并增加后台启动接管。完成状态与恢复数据分别保存，符合现有任务/聊天/图分工。
2. SQLite checkpointer：依赖已安装，学习验证方便，但生产会同时管理 PostgreSQL 与本地数据库文件，不作为本次生产方案；只作为本地恢复测试夹具可选实现。
3. 只重新执行原问题：工作量较小，但重排等已完成步骤也会重做，不满足从图进度继续的目标。

## 持久图与请求上下文

每个生成任务使用服务器生成的唯一 task_id 作为图 thread_id；不能由浏览器任意指定图线程。同一聊天的不同问题使用不同图线程，聊天历史继续从现有消息表读取。

State 只保存可序列化数据：问题、有限历史、资料权限快照、改写、候选、重排资料、完成结果与可序列化计时。logger、trace、线程 Event、模型客户端、数据库连接和进程内 perf_counter 起点移到每次执行的运行上下文，恢复时重新创建。使用官方序列化支持与字段白名单，不开启 pickle fallback。

使用同步检查点持久化模式，确保完成的节点在执行下一节点前落盘。启动检查点连接池由应用生命周期管理，采用独立表，显式迁移，不在第一次网页请求中建表。保持旧顺序执行器和无持久化测试入口的行为兼容。

## 后台启动接管

新增恢复迁移与任务恢复元数据：图版本、权限快照、恢复次数和执行代次。旧任务不自动获得可恢复标记；既有 interrupted/failed/completed 任务不自动重做。

启动时完成账号存储、图与检查点连接初始化，再读取新版本的 running 任务。核验账号仍启用、对话仍归属该账号、当前权限与保存范围一致、图版本兼容后，再恢复。权限变化、账号停用、图版本不兼容或检查点损坏时标记中断并给出安全提示，不使用过期授权。恢复不依赖旧浏览器 Cookie 仍有效；查看仍要求当前登录。

存在检查点时从最新状态继续；任务创建后尚无任何检查点且从未执行外部节点时，从初始输入启动。图已完成时直接使用检查点中的完整 answer/sources 交给原保存事务。图未完成时以恢复调用继续；未完成节点允许重新执行。

恢复任务按创建时间调度，仍每账号一项、全局最多4个执行线程；超过4项的恢复任务等待空位，不丢弃。启动接管先于接受新生成，避免旧任务与新提交抢同一账号。旧 submission_key 继续解析到原任务。

第一版每项任务最多自动恢复3次，避免连续重启导致无界重复执行。普通模型/API失败仍按现有规则 failed，不增加失败自动重试。恢复次数是服务重启接管次数，不是网络重试次数。

## 部分回答与保存一致性

恢复重新执行回答节点前，原部分回答清空；网页显示恢复阶段及重新生成提示，后续按现有任务快照更新。若图已完成，不清空完成结果，直接提交检查点中的完整答案。

后台以完成事件的完整 answer 为最终保存依据，增量仅用于进度展示；这样从已完成检查点恢复时不依赖新 delta。继续使用 complete 的同事务问答/来源/状态提交与 completed 幂等判断。

仅允许一个服务器实例持有恢复运行锁（PostgreSQL 会话级 advisory lock），第二个实例拒绝启动。执行代次校验所有任务进度/完成写入，避免退出中的旧线程覆盖新代次。正常退出先停止调度与请求接管，再关闭正在执行的图并等待线程退出，最后关闭检查点连接；未完成的可恢复任务保留供下一次启动接管。强制结束进程由下次启动同样接管。恢复锁无法续持时停止执行与写入，不能继续发布结果。

## 权限、删除与日志

检查点没有普通用户直接读取/恢复 HTTP 入口。图线程、任务、账号、对话映射在服务器验证。删除对话在沿用生成中拒绝删除的规则下，同时清理其任务对应检查点；失败应可重试清理，已删对话的检查点永不再用于恢复。恢复查询、每次执行和最终保存都保留归属检查。

记录 generation_recovery_started/completed/blocked、task_id、原 request_id、执行代次与恢复次数；重新创建阶段 trace。无密码、Cookie、连接串或整份检查点日志输出。保留原阶段日志，分辨节点重新执行与完成结果仅补保存。

## 迁移、部署与验证

先用当前Python环境做官方checkpointer版本兼容验证，再写依赖；不升级无关组件。生产迁移前归档备份并逐表摘要核对既有数据；仅新增检查点表、任务恢复字段和迁移标记。旧任务恢复字段默认不可恢复。检查点缺迁移时启动明确拒绝，不悄悄降级为重新问答。

测试先行：在重排后与回答中强制终止本地假模型进程，再重启，验证已完成节点不重复、未完成回答重新生成、历史仅一对问答、来源一致；另覆盖图完成但聊天保存前中断、没有检查点的初始任务、重复启动、超过容量待恢复、权限改变、账号停用、损坏与版本不兼容、恢复上限、删除清理和旧任务兼容。使用临时PG schema/SQLite及独立测试进程，不杀生产服务来制造故障。

运行完整后端/前端/浏览器回归，真实浏览器观察后端重启后的原任务恢复。真实部署只在确认当前生成任务状态后进行，保留生产历史，不自动发真实测试问题。不提交或推送HANDOFF；本方案阶段不自动提交或推送代码。

## 验收与学习范围

实施完成和代理测试通过单独记录；用户真实重启验收与概念理解单独记录。按已完成步骤、重新执行节点、聊天保存解释恢复行为，不声称token级续写或所有外部操作恰好执行一次。

不包含长期记忆、工具/HITL迁移、管理员界面、独立任务队列、多实例执行、网络自动重试或SSE展示升级。
