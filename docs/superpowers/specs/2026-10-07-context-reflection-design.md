# 对话摘要与自动长期记忆整理设计

状态：用户已于2026-10-07整体审阅并明确确认；两阶段代码、自动验证、独立审查修复与本机部署完成；用户真实模型验收待进行。实施取舍与限制见v12-16/v12-17及本地执行ledger。

## 目标与现状

当前网页问答通过最近四轮用户问题理解追问，完整聊天记录存 PostgreSQL；没有历史摘要或普通聊天自动提取。两层账号记忆、手动编辑、明确聊天命令、后台问答与图恢复已经存在。历史助手回答不作为法律依据。

本次分两个实施阶段：先升级当前对话上下文，再增加自动记忆后台任务。两阶段共享来源消息范围，但摘要按对话保存，长期记忆按账号保存；不把两者混成一份文本。

## 方案选择

- 每轮单独模型提取：及时，但额外调用频繁。
- 仅关键词触发：便宜，但容易漏掉自然表达。
- 推荐且用户认可：压缩时安排后台整理，短对话通过空闲计时补充；只处理新增消息。关键词不作为自动发现的唯一入口。

## 已认可的产品规则

1. 对话摘要与待压缩历史合计预计超过约 4,000 Token 时触发压缩。这是初始应用预算，不是模型窗口上限或经评测的最优值。
2. 摘要目标 500–800 估算 Token，优先保留最新几轮原文；完整原始消息不因压缩而删除。
3. 摘要保留主题、用户明确陈述的条件、后续纠正、未解决的问题，并保留对应来源。助手历史法律结论不成为确定事实。
4. 需要压缩时同时安排长期记忆检查；未达压缩阈值时，最后回答完成后空闲约 120 秒安排检查。新消息推迟尚未执行的空闲任务。
5. 浏览器关闭不取消任务。待处理范围、预计执行时间和执行进度存 PostgreSQL；服务关闭时暂停，重启后继续。
6. 手动编辑和“请记住”继续及时处理。自动整理由独立开关控制，默认关闭。
7. 清楚、稳定的新偏好或背景可自动补充；重复跳过；临时要求、案件条件不跨对话保存；与现有记忆冲突的内容先提出建议，由用户确认。
8. 旧后台任务不得恢复用户手动删除的内容。

## 阶段一：有来源的对话摘要

将上下文构建与历史存储分开：上下文构建器按已授权账号和对话加载摘要及尚未摘要的消息，不再先裁成四轮再判断长度。摘要登记版本、来源消息范围和处理位置。新对话无旧对话摘要。

初始估算复用项目现有 Token 估算方式，并明确它不等于实际模型计费。触发预算只统计对话摘要与未压缩历史；当前问题、系统提示、检索资料、长期记忆与输出另作完整请求预算校验，不能把资料增多当作需要压缩历史。

压缩后摘要与近期历史的目标合计不超过2,500估算Token，为后续消息留出空间，避免每轮再次触发；这也是待评测起点。尽量保留最新四轮用户原文，但它是保留目标而非不受长度约束的保证。整轮消息选择按预算进行；单条超长输入不能直接截断关键事实，需返回可理解的长度提示，本次不新建合同分析流程。已有摘要加较早消息产生新摘要，不按字符截断摘要。模型无法在目标长度内可靠保存必要条件时，显示上下文整理失败，不静默丢失条件。

摘要用于问题理解与检索改写，回答继续基于本次检索证据。原始用户问题用于记忆相关性选择；助手文本若用于理解代词，必须标明是历史助手说法，不能作为用户事实来源。纠正具有来源标记并覆盖旧陈述。

当前问题依赖新摘要时，摘要生成处于必要的前置步骤；可能增加该轮等待时间，不宣称完全后台化。摘要提交、来源位置更新与任务状态用事务和版本检查保护。恢复复用已保存结果；无法恢复的错误提示用户，不引入无限自动重试。

## 阶段二：自动记忆后台任务

使用独立于问答生成的持久任务表和后台执行器，复用已有服务生命周期与归属校验的模式，不复用明确命令的授权函数来授权自动修改。问答完成及待整理任务登记保持事务一致性，避免回答已保存却遗漏安排。

任务记录账号、对话、来源范围、到期时间、状态、执行代次、开关代次和记忆版本。仅处理已保存且尚未处理的普通用户消息，携带有界前文消除歧义；助手回答不作为用户事实。压缩触发和空闲触发按来源范围去重；同一账号串行保存，已完成范围不重复提取。浏览器连接不拥有执行任务。

初始执行并发为一个记忆后台任务，全局同时运行上限为一；问答优先，新增聊天使尚未开始的空闲任务延期。后台调用设置有限超时、输入输出预算；每轮最多一次提取调用，失败不在普通消息到达时无限反复调用。后端重启可对崩溃中的同一任务恢复一次，超过上限显示失败并允许用户主动重试。外部模型调用无法承诺只执行一次，保存结果必须幂等。

提取结果需包含新内容、建议层级和用户来源原文。服务端验证内容由用户陈述支持，属于稳定偏好或背景，不能根据助手推断生成用户事实；自动路径只补充新内容，不直接删除、替换或重写手动文本。不确定结果跳过，冲突进入待确认建议。

规范化精确重复直接跳过；语义重复由提取结果提出判断并保守处理，不声称已经有最优相似度阈值。沿用当前核心/扩展长度和条目预算；超预算转为建议，不悄悄挤掉旧记忆。新增扩展条目才按现有规则生成向量。

手动保存、明确命令、关闭自动积累、清空或删除必须使旧任务的写入资格失效。旧版本结果不自动重新套用到新记忆，也不根据旧来源重新生成已删除内容；标为失效并保留可追踪原因。将来有新的用户陈述时可产生新的候选，不能把删除理解为永久禁止某个主题。

冲突建议附来源和当前版本，在设置中提供接受/忽略。接受仍校验本人身份、来源范围、开关和当前版本；版本改变则旧建议失效，不覆盖新内容。只在数据库提交后显示“已更新长期记忆”。

## 设置、删除与恢复边界

“使用记忆”和“自动积累”分开显示。自动积累仅在两个开关都开启时运行；关闭使用暂停自动任务，显式编辑仍可操作。用户已在整体审阅中认可此规则。

删除对话取消其待处理任务、移除对话摘要及待确认建议，执行中的任务保存前重新核对来源仍存在。已保存的账号记忆不因删除对话自动删除，界面说明其独立生命周期；用户可在记忆设置删除。摘要、候选和任务输入均为本人私有数据，不能跨账号读取。

正在运行问答使用启动时确定的上下文和记忆。后台保存不得取消正在回答的任务；现有恢复中的记忆版本检查仍可能使未完成图要求重发，需要专门覆盖并明确提示，不自动绕过该检查。

## 日志与量化验证

日志记录任务/来源 ID、触发原因、估算与实际可获取的 Token、调用次数、队列等待、提取/保存耗时、新增/重复/冲突/失败计数。自动整理日志不记录完整私人记忆、候选文本或向量；现有问答日志规则需单独核对，不宣称普通问题从来没有被记录。

先使用假模型和临时 PostgreSQL 验证：阈值上下边界、早期条件保留与纠正、摘要污染、两用户和两对话隔离、长单条输入、空闲重置、浏览器关闭、后端重启、同范围重复触发、手动删除后旧任务失效、冲突确认、开关变化、模型失败与事务失败。

在用户真实验收后，用同批长短对话比较原方案与新方案的追问质量、早期条件保留率、模型调用次数、实际 Token 和等待时间。配置数字与测试数不当作生产提效百分比。
