# V12 账户基础设计

用户已同意先建立 PostgreSQL 账户表和几个示例账户，之后再接网页登录，再实施等级资料权限。本步按该批准范围执行；不新增登录页面、Cookie 会话或实际 RAG 授权，不迁移匿名对话归属。

## 数据与接口

新增 account_levels（稳定等级 ID、显示名）、account_level_libraries（等级 ID、稳定资料库 ID，组合主键）、users（稳定用户 ID、唯一规范登录名、密码哈希、等级外键、是否启用、创建时间）。不使用数值等级继承，也不因资料范围广而授予管理操作权。A/B/C 仍是未来资料库的示例标识，不声称已给现有 Chroma 片段打标签。

三个普通示例账户为 demo_ab、demo_c、demo_abc，等级 level_ab、level_c、level_abc，范围分别 {A,B}、{C}、{A,B,C}。初始密码随机生成；使用 Argon2id（19 MiB、2 次、并行度 1）加随机盐，数据库不存明文。Account 返回值与 repr 不带哈希或密码；验证错误密码、未知或停用账户均返回 None。

数据库新增由 prepare_demo_accounts.py 的显式 --apply 执行，默认只读检查。DDL、映射、账户和 schema_migrations 中的 v12_accounts_v1 标记在事务中写入；已有不同账户、不同映射、不完整结构或未标记的既有完整表均拒绝覆盖或采用。重复执行使用相同本地凭据，保留原 ID、哈希及数据。初始凭据保存在 .demo-accounts.json，先加入 Git 忽略；不在标准输出、请求日志或版本库中输出密码。凭据文件不是数据库提交证明，失败保留它以便用同一身份重试，不生成第二套密码。

读取配置集中到 database_settings.py，保持进程环境优先于 .env 的原规则，复用已验证的独立 PostgreSQL 配置。账户存储在构造时检查迁移就绪，普通查询不自动建表。

## 验证与实际执行

先用真实 Argon2 测试随机盐、正确/错误密码、输入边界及损坏哈希。实际 PostgreSQL 测试仅写随机 account_test_ schema，验证账户持久化、约束、停用/隔离、等级集合、默认只读检查、重复创建不重置、冲突整体回滚和安全输出。CLI 使用临时凭据文件验证其实际行为。

完整回归通过和独立审查后，对本机 legal_rag/public 添加账户表和三个账户；操作前用独立容器 pg_dump 生成忽略目录中的备份，操作后核对所有原聊天表完整记录保持一致。网页仍按原匿名行为工作；登录接入后才强制认证。用户尚未验证账户登录，因为该入口属于下一步。
