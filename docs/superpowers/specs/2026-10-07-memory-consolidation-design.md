# 长期记忆语义整理：第一阶段设计草案

> 已被 `2026-10-07-model-memory-tools-design.md` 替代。本稿保留设计演变记录，三个固定风格维度限制不再是实施依据。

状态：用户要求制定计划；本设计供审阅，尚未实施。下一步在当前对话逐步推进。

## 要解决的实际问题

自然表达“我喜欢先看结论，再看具体例子”与命令“请记住：先给结论，再分点解释”目前分别经过后台提取和命令保存。现实现保留原话、按文字查重，不能稳定识别部分重叠。

第一阶段目标是只保留一份“先给结论”，同时保留“具体例子”和“分点解释”。建议显示为：

> 回答先给结论，再分点解释，并结合具体例子。

显示文字可以整理；证据仍保留用户原话。来源存在只能证明说过这段话，不能证明任意归纳正确。不得将“喜欢举例”归纳为“用户是初学者”。

## 第一阶段范围和选择

1. 统一自然积累与明确“记住”命令的新增逻辑、版本校验和落库方式；直接手动编辑仍有最高优先级。
2. 第一批自动整理限定回答风格：结论先行、分点解释、结合例子。模型将不同说法映射为含义条目，程序按条目合并，不建立一长串触发关键词。
3. 每个条目保留来源和时间；相同含义重复出现增加证据，不增加显示段落。
4. 其他用户明确陈述的背景沿用保守原文保存。开放式背景的语义合并先产生待确认建议，不直接改写。
5. 从多轮话题推测学习背景不在本阶段。例如反复问 TCP，只能考虑“近期学习 TCP”的候选，不能自动宣布其职业。该能力需要独立的证据积累与过期设计。

这一范围是先让你截图中的问题可靠地解决，并建立后续更灵活归纳所需的来源与合并基础，不宣称已经实现 WorkBuddy 的用户画像。

## 保存与显示

PostgreSQL 增加账号所属的含义条目和证据表。继续使用现有核心/扩展文本作为读取投影和用户编辑界面；一次事务同时保存条目、证据、文本、扩展向量及版本。

含义条目包括：id、账号、层级、key、value、显示文本、来源类型、是否手动保护、状态、版本。第一批风格 key/value：

- `answer.order / conclusion_first`
- `answer.layout / bullet_explanation`
- `answer.support / concrete_examples`

证据包括：账号、条目、来源类型、对话和用户消息序号（聊天来源）、原文片段、记录时间。引用必须在本次冻结的用户来源中逐字存在，禁止使用助手回复授权记忆。删除对话后去掉失效的消息定位，保留已保存记忆的来源摘录；账号删除清除条目及证据。该行为在来源界面说明。

来源类型：explicit_command、automatic、manual_document、legacy_document。旧文本仅登记 legacy_document，不伪造历史消息来源。迁移不重新整理旧文本、不调用模型，也不替用户清空重复的验收数据。

用户手动编辑的段落作为受保护段落：自动任务不能重写或删除它；无法确定重复关系时产生建议。手动保存以完整文本为准，退休被删除的条目并更新策略 epoch，旧任务不得将其复活。退休条目的自动重新加入必须等待用户确认；新的明确“记住”命令可以重新授权。

## 写入和冲突

模型只提出候选，不执行数据库操作。新增候选拆成原子含义，程序决定：

- 相同 key/value：合并来源，显示不变。
- 新的已支持 key/value：新增含义并重新渲染该组风格段落。
- 相同 key、不同 value 或其他不确定语义关系：待确认建议。
- 来源错误、临时要求、第三人、案件条件、越界输出：拒绝该候选，现有记忆不变。

“更简短”“更详细”等本阶段未支持的风格仍可原文保存；其语义冲突不自动覆盖。明确删除/替换/清空仍沿用现有授权约束，不能借这次整理扩大模型删除权。对新的风格组需要删除或替换时，用户目标必须唯一；含糊目标要求澄清。

自动条目的渲染顺序固定为结论、解释布局、例子；受保护段落保持用户顺序和文字。不能因为模型输出了一个好看的摘要就丢掉已有含义。新增后超过预算时产生容量建议，不静默截断。

后台与明确命令均使用冻结来源、冻结记忆版本。提交重新检查账号归属、当前 revision、开关/epoch、原文及候选合法性；不在数据库锁内调用模型。冲突返回或过期作废，不能盲目把旧结果覆盖新编辑。

## 成本和边界

- 不新增每问一次模型扫描；自然积累仍在空闲约 120 秒或上下文整理后批处理。
- 同一批既提取也归纳，沿用一次整理模型调用；不增加第二次在线模型“裁判”。明确命令沿用已有的一次解析调用。
- 开关关闭仍不自动保存；收到偏好与保存成功分开反馈。
- 保留核心 500 估算 token/1500 字符，扩展 12000 字符/40 段/每段 1000 字符，检索最多 3 段/500 估算 token。
- 核心不向量化；扩展仅内容变化时更新向量，证据增加不重新向量化。
- 保留账号隔离、来源范围进度、幂等、手动编辑保护、浏览器关闭后的后台处理和回答任务优先。
- 本轮仅规划；不操作用户记忆、不迁移、不重启、不调用付费模型、不提交推送，HANDOFF 仍只在本地。

## 评测和用户验收

固定样例覆盖同义改写、部分重叠、顺序变化、新信息、否定、临时要求、第三人、引用、案件条件、手动覆盖、跨账号、任务重放、删除后回放及容量。

记录重复含义数、新信息保留数、无依据新增数、覆盖手动内容次数、模型调用数、输入输出 token、整理耗时。比较原方案和新方案时使用同一批输入与相同模型设置；确定性夹具只验证程序边界，不能当作真实模型语义效果。未经测量不写提升百分比。

程序验证完成后，由用户自行创建测试对话、发送截图中的两句话、等待整理、查看一份“先给结论”和两项新增偏好；再新建对话检查使用效果。助手不代用户保存、清空或重试完成验收。
