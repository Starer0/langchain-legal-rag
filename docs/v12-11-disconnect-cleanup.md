# 生成期间刷新后的会话锁清理

用户在生成中刷新后，再发问题持续收到 409。实际请求日志显示原 SSE 已 disconnected，但会话锁仍占用。

原因：同步事件生成器只在自身 finally 释放锁，StreamingResponse 的线程池迭代包装在断开时不保证关闭原生成器；若流尚未启动，生成器 finally 也不会执行。

修复：响应拥有原生成器，在 ASGI 调用结束时用受取消保护的线程池清理关闭它；生成器和响应共用幂等 release_once，避免二次释放影响后来请求。断开时等待正在执行的线程池迭代结束，不能先释放锁让同一对话并行写入。

回归测试 tests/test_web_disconnect.py 覆盖：首次正文发送时断开、响应头发送时断开、计算期间断开。前两个原先失败 409，修复后通过。检查半成品不入库、后续请求可以保存完整回答，以及计算未结束时仍拒绝并行请求。

这项修复处理断开清理，不提供刷新后的任务续跑、自动重试或请求恢复。已经完整保存的问答仍可从数据库恢复；中断且未保存的问题需重新发送。同步模型调用可能需要先返回，清理才完成。
