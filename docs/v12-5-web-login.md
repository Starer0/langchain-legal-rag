# V12：网页强制登录与账户聊天归属

这一小步将已有示例账户接入现有 FastAPI / 静态网页。打开网页先检查登录状态，未登录不能访问聊天接口；登录后创建、查看、重命名、删除和问答均使用服务器确认的用户 ID。

## 本步行为

- `POST /api/auth/login` 核验已有密码哈希，生成随机会话；`GET /api/auth/me` 检查身份并续期；`POST /api/auth/logout` 撤销当前浏览器会话。
- PostgreSQL `login_sessions` 保存令牌 SHA-256、用户、CSRF 随机值及时间。原始登录令牌只放 HttpOnly Cookie，不放网页存储或请求日志。
- 有效期为三天。打开 / 刷新页面的身份查询和成功的业务请求续期；静态文件及后台闲置不续期。已经过期的会话无法续期复活，退出立即失效。
- 同一个账号从其他浏览器登录，可以查看该账号的聊天。退出一个浏览器不会退出其他浏览器。登录状态变化会清空当前页面的私人内容、取消旧请求，并拒绝旧请求的延迟更新。
- 初次登录要等对话初始化后才能发送；列表加载失败显示提示，可刷新重试，后续身份检查也会重新初始化。
- 旧匿名聊天保留原归属，不自动划给示例账户。所以第一次登录示例账户看不到以前的匿名聊天。
- 修改接口要求 CSRF 请求头，并拒绝明确的跨站来源。登录失败限流按实际连接 IP，不信任客户端转发头。Cookie 为 HttpOnly、SameSite=Lax；本地 HTTP 的 Secure=false，HTTPS 部署需配置 WEB_SECURE_COOKIES。

## 数据与代码

`prepare_web_login.py` 默认只读，显式 `--apply` 在事务中增加登录表、迁移标记和 `conversations.user_id`。每个对话只能归属匿名会话或用户中的一个。`PostgresUserConversationStore` 使用用户归属查询；旧匿名存储实现仍可用于隔离测试。

`login_sessions.py` 管理持久会话；`web_auth.py` 保护 API；`web_app.py` 接入登录路由并在启动时核对准备状态，产品入口不悄悄退回匿名模式。`web/static/auth-client.mjs` 管理页面身份和 CSRF；`app.js` 在异步请求后检查身份版本，避免切换账号后旧结果覆盖新界面。

## 用户验收与边界

打开 `http://127.0.0.1:8001`，使用本地 `.demo-accounts.json` 中已有的用户名和密码。先登录 `demo_ab`，问一条问题并刷新；再从另一浏览器用相同账户确认历史。退出后登录 `demo_c` 应看不到 `demo_ab` 的聊天。无需重复已经确认成功的 PostgreSQL 迁移或 V11 工具练习。

本步实现的是身份与聊天归属。A/B/C 等级资料集合仍仅是账户配置，真实 RAG 检索、上下文和引用尚未按等级过滤；图状态持久化、任务恢复、重连、重试、防重复、长期偏好、React 和阶段召回日志继续按计划后续推进。
