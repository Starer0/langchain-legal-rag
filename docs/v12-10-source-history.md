# V12.10：保存历史回答的来源快照

回答完成后网页可以显示来源，但此前数据库只保存问答正文，刷新后附件消失。本步将最终 `done.sources` 与对应助手消息一起保存，历史接口读取时恢复，沿用已有 React 来源展示。

## 保存与读取

新增 `conversation_sources` 表，以 `(conversation_id, ordinal)` 关联到唯一消息。PostgreSQL 用 JSONB、SQLite 用 JSON 文本保存；复合外键随消息删除级联清理。仅有来源的助手回答写附件，旧消息和无依据回答不补造来源。

快照白名单包含资料名称/法条/页码/正文、现有版本与稳定标识及资料库标签等最终来源信息，不保存召回候选或运行凭据。保存问题、回答、快照及标题更新是同一个事务，任何一步失败整轮回滚，成功提交后才发 `done`。

历史展示通过 `load_conversation_history` 读取附带来源的消息；原 `load_conversation_messages` 保持角色/正文二元组，供追问的模型上下文使用。因此来源持久化不会自动增加每次追问的上下文或Token成本。历史读取按当前已认证用户对对话的归属校验，其他账号即使知道ID也不能访问。

快照保存当时的内容，知识库随后更新不会改写旧附件；快照不保证被引用法规永远有效。账号资料范围变更后的历史正文和附件统一撤回属于后续数据访问规则，不在本步仅对来源单独实现。

## 迁移与兼容

先备份 PostgreSQL，然后在项目根目录运行 `python prepare_source_history.py` 只读检查，`python prepare_source_history.py --apply` 执行新增表迁移。迁移事务有锁与幂等标记，重复执行 `already_ready`；发现未标记同名表拒绝覆盖。正式认证存储启动检查迁移，缺失时明确报错。

SQLite 自动添加独立附件表，不修改既有消息表列结构。旧 SQLite→PostgreSQL 导入工具对非空来源快照明确拒绝，避免悄悄丢失新数据；从带附件的 SQLite 整体迁移需后续专门方案。原有无附件迁移保持兼容。

本机迁移前自定义格式 pg_dump 备份及归档目录校验完成；迁移前后所有既有数据表逐行摘要一致，仅新增空附件表与迁移标记，账号、旧聊天和权限未改动。

已更新实际8001服务，代理只读核验真实账号登录/历史/退出，没有向生产库写入测试问答。用户可新提问一次、展开来源、刷新后再次展开，完成本小步网页验收。旧问答没有附件，不能用它们判断本次保存功能。
