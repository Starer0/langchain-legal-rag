# V11.7：有上限的 Agent 工具调用循环

## 与上一步有什么区别

V11.6 的工具流程固定为“请求一次 → 执行 → 回答”。本步在已有结果之后，再让模型选择继续调用还是结束，同时由程序限制成本。

流程为：

```text
tool_plan → execute_tool
                ↓ 第一次成功
           tool_continue
            ├→ 没有新调用：模型已经给出答复 → END
            └→ 新调用：execute_tool
                          ↓ 达到两次上限
                      tool_answer → END
```

没有初次工具请求时仍走 RAG。工具校验失败时直接结束工具路径，显示错误，保留此前成功结果。我们没有把所有法律问答改成 Agent。

模型决定下一次工具名称、参数与是否提前结束；Python 负责允许列表、参数校验、执行和次数上限；LangGraph 负责条件边与循环。这符合[官方工作流与 Agent 的区别](https://docs.langchain.com/oss/python/langgraph/workflows-agents)：路径可以由代码规定，工具使用也可以交给模型动态选择。

## 运行与观察

在项目根目录运行：

```powershell
python main.py --langgraph --tools --agent-loop --trace --profile
```

提问：

```text
2026年10月1日到15日，以及2026年11月1日到20日，哪个区间更长？长多少天？
```

希望观察到：

1. tool_plan 提出第一个区间的请求。
2. execute_tool 返回 14 个自然日，累计 1/2。
3. tool_continue 收到第一个 ToolMessage，提出第二个区间的请求。
4. execute_tool 返回 19 个自然日，累计 2/2。
5. tool_answer 比较结果，第二个区间长 5 天。

模型也可能先计算第二个区间；参数顺序由模型决定，不能把这种变化当作错误。若模型只计算一个区间就结束，trace 会显示提前结束；此时需要检查答复是否确实有足够的工具结果支持，而不是只看答案听起来正确。

再问单区间问题，例如“2026年10月1日到15日相隔几天？”，观察模型是否执行一次后直接回答。问“试用期最长多久？”应回到原来的 RAG。

省略 --agent-loop 仍是 V11.6 的单次工具模式；省略 --tools 则没有工具选择开销。本步也可结合 checkpoint，但 checkpoint 当前仍不支持 --profile。

## 如何确保循环会结束

每轮只接受一个格式正确的工具请求。成功执行次数累计到 State 的 tool_call_count；达到 MAX_TOOL_CALLS=2 后，图不会再次进入工具决策节点，而是调用未绑定工具的模型作最终答复。即使模型倾向继续，也不会执行第三次工具。

最终提示词要求只比较已经取得的结果：超过预算、尚未计算的区间必须说明缺少工具依据，不能把没执行的计算当作已取得的结果。这里没有全面评测模型的停止决策或答案忠实性，不将代码次数上限等同于模型一定能完成任意复杂问题。

为观察串行循环，循环模式绑定模型时设置 parallel_tool_calls=False；当前配置 API 已接受该参数。参数说明见[官方模型工具调用文档](https://docs.langchain.com/oss/python/langchain/models#tool-calling)。同时仍保留程序的单请求校验，不能只相信提示词或 API 参数。

## 状态和成本

- tool_messages：原始问题、模型请求和相应的 ToolMessage；每个结果消息关联原调用 ID，后续模型能读到以前的结果。
- tool_results：本轮所有成功计算结果，不只保存最后一条。
- tool_call_count：本轮已成功执行的工具次数。
- tool_request：当前模型新提出的请求。

这些字段在新问题开始时重置，防止上一轮结果进入本轮。当前按完整列表覆盖更新；没有引入 reducer 自动累加，累加由节点显式返回新列表完成。

一次工具后模型提前结束，通常是两次模型调用。执行两个工具后强制最终回答，通常是三次模型调用：初次选择、工具后决策、最终答复。本地日期执行不算模型调用。普通 RAG 仍比未开启工具模式多一次初次选择。

## 本步范围

这是单工具、最多两次执行的学习循环，不涉及通用工具平台、MCP 接入或完整多用户 Agent 产品。日期工具仍只算自然日间隔，不判断法律期限或工作日。

用户要求任意关闭窗口、后台崩溃、重连与失败恢复在 V12 的真实软件设计中落实；本步不增加独立故障模拟练习。

自动测试使用真实日期函数与 LangGraph，加本地模拟模型消息，覆盖两次结果的积累、关联 ID、提前结束、上限、错误停止、RAG 回退、checkpoint 清理、CLI trace 和模型调用计数。学完后应能解释：模型做了哪次决定、程序在哪处限制了次数、第二次模型怎样拿到第一次结果。

真实 API 验证：两个区间问题走 tool_plan → execute_tool → tool_continue → execute_tool → tool_answer，工具分别返回 14 天、19 天；最终答复第二个长 5 天，成功工具执行 2 次、模型调用 3 次。初次测试有过单请求格式校验失败，后来为循环模式加入关闭并行请求参数后完整链路通过；这不代表所有输入的模型选择都已经评测通过。
