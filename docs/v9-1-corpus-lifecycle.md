# V9.1：知识库变更检测与导入状态

## 要解决的问题

知识库资料不是一次导入后永远不变：PDF 内容、目录中的版本信息和 Embedding 配置都可能改变。导入前需要先知道当前索引是否仍对应这些资料。

## 使用方式

正常启动命令行问答时，系统会先自动执行这项检查：

```powershell
python main.py
```

资料和索引一致时直接进入问答；资料未建立或已变化时，会先自动执行一次导入，再进入问答。`--ingest` 仍可用于手动导入。

若只想查看状态、不进入问答也不导入，可运行：

```powershell
python main.py --corpus-status
```

该命令是只读的：它会读取资料目录、PDF 文件指纹和已发布的 `manifest.json`，但不会解析 PDF、生成向量、写入 Chroma 或调用模型。

可能的结果：

```text
知识库已就绪，无需重新导入。
知识库资料或配置已变化，需要重新导入。
尚未建立知识库，需要先导入。
```

当需要重新导入时，命令会列出新增、已修改、已移除的资料；若 PDF 文件未变化但资料目录或 Embedding 配置变化，也会明确说明。

随后再运行：

```powershell
python main.py --ingest
```

## 当前设计

Manifest 现在保存每份资料的：

```text
资料 ID
资料类型（法律 / 指南）
文件名
版本
SHA-256 文件指纹
```

文件指纹可以理解为 PDF 内容的“指纹”：即使文件名没有变，内容被改过也会不同。

V9.1 只做变更检测，重新导入仍沿用原来的安全整体重建：先建立新的版本化 Chroma collection，检查完整性后才原子替换 Manifest。这对当前 259 个 Chunk 的小型知识库更简单可靠。

真正的增量更新会在资料规模足够大、整体重建成本明显上升时再引入；届时需要额外处理删除旧 Chunk、失败回滚和索引一致性。
