# V12.17：后台积累长期记忆

在已有手动编辑、明确记忆命令之外，设置中新增“自动积累长期记忆（后台处理）”，默认关闭。开启后只处理后续已保存的普通用户消息；还必须开启“在回答中使用记忆”。两者独立，关闭不会删除已有文本。

## 时机和费用

上下文压缩成功后安排整理；短对话在最后回答完成后约120秒空闲安排。新问题推迟尚未开始的空闲任务，正在运行的问答优先于待领取记忆任务。计时、范围和进度在服务器/PG，关闭浏览器不取消。服务器停机期间暂停，下次启动继续。

单进程持有现有检查点服务租约，只有一个后台整理线程。每批最多4000估算 Token 的新用户消息，携带最多1000的用户前文；较长范围分批，单条超长则可见失败。每次尝试只调用一次提取模型，20秒超时、无客户端重试。扩展记忆新增时可能还需要向量生成。不是每个问题额外提取。

模型失败后显示失败，后续普通聊天不反复提取失败旧范围；主动重试仍需来源/开关/版本有效。进程在执行中崩溃可接管一次，不能保证外部API恰好调用一次；数据库保存和进度具有幂等保护。

## 保存与确认

- 稳定的新偏好/本人背景可追加；初版要求内容逐字来自用户短句，并保守检查稳定意图。
- 精确重复跳过；模型报告同义重复也跳过，但不是经评测的语义去重算法。
- 临时要求、案件日期金额条件、第三人、假设与歧义跳过。规则是保守中文起点，会漏掉某些自然表达；原文引用也不证明用户陈述客观真实。
- 与旧偏好冲突先显示当前内容和建议内容，用户接受才进行指定替换。容量不足只建议手动精简，不自动删除原记忆。
- 设置轮询只在可见且无草稿修改时更新。等待/执行中不会显示“已更新长期记忆”；提交成功后才显示。

核心500估算 Token/1500字符、扩展12000字符/40段/每段1000字符沿用原实现。自动保存不改变已有文字；手动保存/清空/明确命令/开关变动会递增资格代次并使旧来源失效，因此旧后台任务不能把删除内容重新补回。

## 工程与隐私

新增policy/progress/job/suggestion四张PG表，回答完成与任务登记在同一事务。提交前复核活跃账号、对话归属、来源原文、开关代次、任务代次和记忆版本。API沿用登录/CSRF，数据不缓存；任务安全状态不返回完整输入或向量。

提取日志只记任务标识、范围、调用数、耗时、结果计数及可用的实际token用量，不记提取原文。现有普通提问/RAG日志仍可能保存问题与检索片段，不能把本次元数据日志策略理解为旧日志无私人信息。清空设置不等于日志/备份所有副本立即删除。

迁移入口`prepare_memory_reflection.py --apply`，服务启动不自动迁移。测试使用临时真实PG、假模型和Chrome，包括浏览器关闭与后端进程重启。真实模型的误提取/漏提取、延迟、费用及个人表达覆盖率仍待用户验收和同批问题评测；不等同于WorkBuddy实现。
