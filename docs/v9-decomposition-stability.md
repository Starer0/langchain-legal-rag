# V9：复杂问题拆分稳定性开发评测

## 目标

先测量拆分是否稳定，再决定是否修改拆分提示词或检索预算。题面应有多少个独立法律意图，与模型实际输出多少个子问题分开记录。

## 开发题集

`evals/decomposition_stability_cases.json` 包含 4 道题，分别预期拆为 2、3、4、6 个子问题。题目覆盖试用期期限与工资、节假日加班、违法试用期赔偿、仲裁时效和仲裁申请书内容。

评测入口：

```powershell
python run_decomposition_stability_evaluation.py --run-id <direct>
python run_decomposition_stability_evaluation.py --run-id <rewrite-first> --rewrite-first
```

第一条命令直接将原问题交给拆分器；第二条先经过同一套 History-aware Rewrite 的无历史分支，再交给拆分器。每题保存改写后的检索问题、实际子问题和数量匹配结果，供人工检查是否有语义遗漏或重复。

## 基线结果（2026-09-29）

```text
直接拆分：4 / 4 题的子问题数量与预期相同。
Rewrite 后拆分：4 / 4 题的子问题数量与预期相同。
```

人工检查显示，两种路径均保留了题目中的工资、加班、赔偿、时效和申请书等独立诉求，没有出现明显重复。

## 结论与限制

这说明当前拆分提示词能处理本开发集中的明确多意图题，因此本轮不修改提示词、不增加模型调用，也不以这 4 道题为依据默认开启复杂问题拆分。

该题集很小，且问题明确罗列了各诉求；它不能证明对口语化、交织事实、办事指南混合问题或资料不足问题同样稳定。下一轮应扩展这类边界题，并保留人工语义检查；冻结的独立保留题集只在规则稳定后运行一次。
