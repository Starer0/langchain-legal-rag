# V12.18：纯回答偏好与法律问题分流

普通消息进入 LangGraph 时，先以保守规则判断是否是完整的个人回答风格偏好。
例如“我喜欢先看结论，再看具体例子”进入 preference 节点，返回简短确认，来源列表为空，
不执行问题改写、检索、重排、记忆选择或法律回答模型调用。
确认收到不等于长期记忆保存成功，实际整理结果仍以设置页面为准。

偏好回复读取本次任务冻结的账号自动积累策略：关闭时明确不会自动保存，
开启时说明等待后台整理；“在回答中使用记忆”关闭时说明后台积累暂停。
策略与任务记忆快照在同一个账号锁保护下读取，不借用其他账号设置。
这一修复经69项后端检查、桌面/手机2项浏览器验证，包含关闭时提取调用为0、
开启后积累及重启恢复；测试数据隔离，不代用户切换开关或操作记忆。

明确的记忆编辑命令仍走 memory_command；若同时含法律提问、疑问式追问或单独法律说明请求，
则继续 RAG，不直接执行记忆编辑。“请解释结论”等追问不会判为回答偏好。
第一版不是通用意图模型，不能覆盖所有自然语言表达；无法识别的消息保守回到原有 RAG 流程。

纯偏好消息及对应回复不会进入后续法律问题改写历史；摘要来源也排除纯偏好。
它们仍保存在聊天记录，并由原有完成事务安排后台记忆任务；整理开关、两分钟等待、
版本与账户权限规则保持原状。本次未迁移数据库，也不回写旧聊天答案。

web_intent.py 使用有界词表扫描，避免重叠正则词引起指数回溯。
web_langgraph.py 增加 preference 节点，图版本更新为 web-rag-intent-v1。
部署前必须等待现有问答与后台整理任务结束；旧图的未完成任务不能直接跨版本恢复。

验证：新分流回归先复现误检索/历史污染，然后通过；相关119项Python验证含临时PostgreSQL，
最后边界修改后23项图/记忆/上下文检查通过；桌面1440及手机375浏览器验证2项通过，
包含不附来源、关闭页面与重启测试服务后后台记忆完成。所有测试用隔离数据、假模型，
没有代用户保存、清空、重试其账号记忆，也没有实际模型调用。

量化记录：识别到的纯偏好前台模型调用数为0，法律检索/重排调用数为0；后台提取仍独立运行。
不将这些调用数直接换算为整体成本或时延下降百分比，实际比例待同批真实问题测量。
