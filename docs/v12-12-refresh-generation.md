# 浏览器刷新后继续生成

## 当前行为

React 提交任务，服务器独立执行；网页通过约 800ms 一次的任务快照查询显示进度。生成过程约 200ms 合并一次进度持久写入；完成事务保存完整问答、来源与 completed 状态。生成中的问题先保存在任务表，未完成内容不进入模型聊天历史。

关闭或刷新页面不取消生成。再次登录同一账号，读取其活动任务并恢复问题、部分回答和转圈；已完成则读取完整历史。失去接受响应时先查询任务，不自动重复提交。提交编号去重；每账号最多一个运行任务，全局最多4个生成线程。

所有任务接口位于受现有认证/CSRF保护的 `/api/conversations/...`。资料范围由服务器确认；任务状态、历史和任务提交均按账号归属检查。运行对话不能删除，检查与删除同事务。历史和任务状态在同一事务、对话锁保护下读取，避免完成瞬间读到不一致结果。

## 部署与边界

先执行 `python prepare_generation_tasks.py --apply`，再启动项目；生产迁移必须先备份。仅支持一个 Uvicorn 进程（当前启动命令不设置 workers）。后端启动和正常退出把 running 标记 interrupted，不重做模型调用。非正常退出在下一次启动处理；页面显示服务重启中断，可重新发送。

这不是重启后自动续跑，也没有自动重试、独立队列或多进程任务协调。生成期间保持原界面规则：可浏览其他聊天，禁止新建、修改、删除、退出和另一条生成。部分回答为任务快照，最终来源仍是历史快照。任务问题与状态留存在 PostgreSQL，可随对话删除级联清理。

日志区分 HTTP 接受/状态查询和 generation_started/completed/failed，并以 task_id、request_id、user_id、conversation_id 关联；RAG 阶段日志保留。

## 验证

301 Python、27 React、类型/生产构建、10 Chrome 浏览器测试通过。真实 FastAPI + SQLite + 阻塞假模型测试1440/375px：发送、刷新、关闭页面、新页面恢复、切换其他聊天、释放模型、恢复答案/来源、再次刷新；模型只调用一次，完整问答仅两条消息。没有调用真实远程模型或添加生产测试聊天。

独立审查发现历史读取与删除的竞态，均已改为事务锁定并复查通过。生产数据库迁移前归档备份完成；既有表数据逐行摘要保持一致，仅新增空 generation_tasks 和迁移标记。
