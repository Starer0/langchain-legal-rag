# 网页问答重启恢复

## 当前行为

生产 React/FastAPI 问答使用 PostgreSQL 检查点。每个生成任务的服务器 task_id 是独立图线程；不同问题不共享图 State。同步保存节点边界；日志、计时对象、取消 Event 放在运行上下文，不写入检查点。

后端启动接管新版 running 任务，按创建顺序调度，每账号最多一项、全局最多4项。恢复沿用原任务和提交编号；重新确认账号仍启用、对话归属、资料范围一致及图版本兼容。旧版任务没有恢复标记，继续按原规则标中断，不补造检查点。

未完成回答节点从该节点重新执行，旧部分内容被替换，页面提示“服务已恢复，正在重新生成完整回答”。已经完成且落盘的图从完成结果补保存聊天，不调用模型。最终答案以 done.answer 为准，与问答/来源/任务 completed 同事务提交；completed 任务不再执行。

每任务最多自动恢复3次。普通模型/API异常仍 failed，不在应用层自动重试；权限或检查点不兼容标 interrupted。不是从最后一个 token 续写，未完成节点可能重新调用外部服务。

## 运行一致性

仅支持一个后端实例。进程持有 PostgreSQL advisory lock；第二个实例启动拒绝。锁失效时调度器停止并取消运行任务。执行代次同时保护任务写入和检查点写入：检查点使用官方 PostgreSQL serializer/SQL，并在事务里锁任务、校验代次；旧线程不能覆盖新执行。

发布进度、节点边界和保存完成前重新核验权限。退出时取消并等待工作线程，再关闭检查点资源。关闭正在执行的节点不会生成缺少结果的终止检查点。

删除非生成中的对话会在原删除事务中登记检查点清理任务；清理失败保留待清理记录，下次启动重做。删除对话的检查点不再有恢复入口。无用户直接读取或任意选择图线程的接口。

## 部署

安装 requirements.txt 中的官方 langgraph-checkpoint-postgres 与 psycopg3/pool。仅本步骤验证版本为3.1.2、3.3.6及pool3.3.3；LangGraph仍1.2.11。已有应用存储继续使用psycopg2，检查点连接使用psycopg3。

先备份，再执行 `python prepare_web_recovery.py --apply`，然后启动 `python -m uvicorn web_app:app --host 127.0.0.1 --port 8001`。public 新增 generation_recovery 与 checkpoint_cleanup；官方检查点在 public_graph 独立 schema。没有迁移时明确拒绝启动，不退回从头生成。

本机迁移前备份：data/backups/legal-rag-20261006T044753Z-0f199dbc-pre-web-recovery.dump，旁边verification.json保存前后逐表摘要。既有数据表逐行摘要一致；迁移新增的恢复元数据为空。

## 验证与边界

337 Python测试（含临时真实PG）、27 React、类型/生产构建、12 Chrome浏览器测试通过，2项依赖弃用警告。14项恢复测试覆盖检查点关闭重开、真实测试进程强制结束、回答重新执行、完成后补保存、权限变化、执行代次、恢复次数、旧任务、排队容量、删除与官方PG saver单实例锁。

1440/375px浏览器使用真实FastAPI+LangGraph+SQLite与本地假模型：生成半段后终止后端测试进程，原页面观察恢复，旧半段消失，新回答生成，刷新后问题/来源保持；已完成改写/检索/重排各一次，回答调用两次，历史仅一对问答。

独立审查三个发现均有回归测试修复并复查通过。没有调用真实远程模型或创建生产测试聊天。用户真实运行验收另记录，不把代理测试当作用户理解。

本步不实现长期记忆、工具/HITL迁移、更多自动重试、多进程执行、独立任务队列或SSE展示升级。应用仍通过800ms任务查询显示内容。本步没有自动提交或推送。
