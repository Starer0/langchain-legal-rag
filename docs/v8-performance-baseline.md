# V8：问答耗时与调用次数基线

本版只增加可选的观测能力，不改变检索范围、重排规则或回答提示词。运行 python main.py --profile 查看普通模式每轮的耗时；运行 python main.py --decompose --profile 查看拆分模式。不开 --profile 时不返回性能记录，仍使用原回答链。

记录每轮总耗时，以及 Rewrite、Decompose（若启用）、Chroma、Reranker、最终回答的阶段耗时与应用层调用次数。Chroma/Reranker 在拆分模式下按各子问题累加。pipeline 阶段包含检索、重排与回答，因此不能再与这些子阶段相加；启动加载知识库的耗时也不属于单轮耗时。模型调用次数是应用层尝试次数，不包含服务商内部重试，也不是精确的 Token 用量或货币成本。记录中不保存密钥、问题原文或完整回答。

## 可重复的三题对照

题集固定在 evals/performance_cases.json，包含单一法律问题、两部法律问题和三法律点复合问题。运行：

    python run_performance_baseline.py --run-id <新的唯一名称>

脚本对同三题分别运行普通与拆分模式，每题均清空对话历史；记录各模式首次构建服务的耗时、每轮性能、来源法条标识和预期法条是否完整进入最终来源。结果写入被 Git 忽略的 evals/results/<run-id>/performance.json。它不保存问题文本或回答文本，也不会覆盖已有 run ID。

2026-09-25 首次真实运行：v8-performance-baseline-20260925。当前本地配置为 Chroma Top 8、Reranker Top 5。数字单位为秒，来自单次网络运行：

- 单一法律题：普通 8.66 秒（模型 2 次、重排 1 次），拆分开关 12.14 秒（模型 3 次、重排 1 次）；两边均完整命中预期法条。此题在拆分模式下仍只有一个检索问题，但多了一次“判断是否拆分”的模型调用。
- 两部法律题：普通 27.49 秒（模型 2 次、重排 1 次），拆分 55.20 秒（模型 3 次、重排 4 次）；两边均完整命中。拆分模式中，单是生成子问题就用了 26.49 秒。
- 三法律点题：普通 25.15 秒（模型 2 次、重排 1 次），拆分 24.33 秒（模型 3 次、重排 3 次）；普通模式没有完整命中预期法条，拆分模式命中。

在这次运行中，Chroma 每轮累计约 0.14～0.53 秒，Reranker 约 0.34～1.37 秒；最终回答生成和偶发的拆分生成占用更多时间。服务初始化第一次约 3.36 秒、第二次约 0.94 秒，运行顺序和缓存不同，不能据此比较两模式启动快慢。

这只是三题各跑一次，远端模型延迟会波动，且未逐题审查答案质量。**不能从这些数字推断拆分模式普遍更慢或更好，也不据此调整检索策略。**后续如决定优化体验，应先增加重复测量并区分模型首字延迟、生成耗时和 Token 用量；本版仅建立可观测的起点。
