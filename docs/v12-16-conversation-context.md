# V12.16：有来源的对话上下文

完整聊天记录仍保存在 PostgreSQL。本次新增摘要与任务输入快照；每次提问读取当前对话的摘要和尚未摘要的用户消息，不再先裁为四轮。助手历史法律判断不作为用户事实或法律依据。

## 预算与流程

- 摘要与待压缩用户历史超过4000估算 Token 才请求一次整理；普通短对话不调用摘要模型。
- 摘要目标500–800，硬上限800；尽量保留最近四轮用户原文，摘要加近期原文最多2500。
- 摘要只选有来源序号的用户原文，区分主题、陈述、纠正、未解决问题。已有摘要条目保留，后续纠正排序在后。语义是否完整、模型是否正确理解纠正仍需真实模型评测。
- 无法安全压缩时返回错误，不切掉半句。长时间积累的旧条目可能超过800，此时需要缩小问题或新建对话；目前不是无限滚动摘要。
- 摘要用于问题改写与检索理解。最终回答仍使用本次授权的法律检索资料；摘要不出现在引用来源。

完整请求另作16000输入估算 Token 预算，输出最多4096；这些是应用限制，不是模型容量。输出长度截断不提交为完整法律回答。模型调用有限超时20秒、无客户端自动重试。

2026-10-07核对配置为`deepseek-v4-flash`、官方端点。官方目前接受该旧名称，由最新Flash服务；官方容量高于本应用限制，实际计费与token仍以API返回为准。[官方模型说明](https://api-docs.deepseek.com/api/responses)、[容量说明](https://api-docs.deepseek.com/quick_start/pricing/)。没有付费调用验证。

## 存储与恢复

`conversation_contexts`按账号和对话保存摘要版本、处理位置、原文来源；`generation_context_inputs`在接受任务的同一事务冻结本轮历史。摘要与可复用结果同事务保存。重启可复用已保存结果，避免摘要已写入但图未检查点时再次生成。

迁移必须显式运行`prepare_conversation_context.py --apply`。新图版本`web-rag-context-v1`会阻止不兼容旧未完成图自动续跑。删除对话级联删除摘要和任务输入；已有备份、日志、检查点的物理清理遵循原方案，不声称所有副本即时擦除。

## 验证与待测

临时真实PG和假模型测试覆盖来源、预算、版本、删除、恢复、权限及错误。Chrome桌面/375px测试覆盖早期条件保留、刷新、新对话隔离。测试通过不等于实际语言总结准确率；早期条件/纠正/法律来源的真实长对话验收仍由用户完成。量化入口见`evals/evaluate_context_reflection.py`，默认只跑固定假模型，不伪造成本下降百分比。
