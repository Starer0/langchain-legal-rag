# V8.3：异构文档接入与结构化切分

## 新资料

`data/劳动争议仲裁办事指南.pdf` 是一份 7 页的虚构办事指南。它不含 RAG、Chunk 或评测提示，只保留“虚构示例”的普通免责声明。

目录、封面不入库。`data/guides.json` 显式登记正文从第 3 页开始，避免目录中的标题被误判为正文。

目录还登记 `routing_topics`，以简短主题词说明指南覆盖的业务范围。问题改写模型只读取这份目录卡片，不读取整份 PDF；它在原有一次改写调用中额外返回是否需要同时检索办事指南。

## 切分规则

本次没有使用固定字符数切分。知识单元由文档结构决定：

- 三级标题对应一个 Chunk；
- 第二章的 8 个办理步骤作为一个完整 `procedure` Chunk；
- 时限表转为“环节、时限、起算点”的行文本，作为一个 `table` Chunk；
- 每组常见问答的题目和答案绑定为一个 `faq` Chunk；
- 特殊情形各自作为一个 `scenario` Chunk。

最终得到 21 个指南 Chunk。每个 Chunk 带有 `document_id`、`document_type`、`title`、`source_file`、`chapter`、`section`、`pages`、`chunk_kind` 与 `index_status`。

法律条文继续保留 `law_id`、`law_name` 与 `article`。所有可检索资料统一使用 `index_status=active`；用户明确指定法律时，`law_id` 过滤仍只返回该法律的条文。

问题改写调用返回 `retrieval_question` 和 `include_guide`。当用户点名某部法律且 `include_guide=true` 时，检索范围为该法律的条文加全部办事指南；若问题还指定了条号，条号只约束法律分支，指南分支照常保留。模型输出无效或无法判断时，`include_guide=null`，系统退回全库检索，避免严格过滤漏掉资料。原始问题显式出现“办事指南”时也会保留指南分支。

## 验证

2026-09-28 重建的 Chroma 索引包含 280 个知识单元：259 条法律条文和 21 个指南 Chunk。

以下六个相近问题在 Chroma Top 8 中命中预期指南 Chunk，并在本次 Rerank 结果中均排第 1：

- 劳动仲裁整个流程通常需要多久 → `2.1 全流程预计时长`
- 仲裁裁决一般多久作出 → `5.1 仲裁裁决一般多久作出？`
- 申请劳动仲裁收费吗 → `4.2 费用说明`
- 请律师代理仲裁的费用由谁承担 → `5.3 请律师代理仲裁的费用由谁承担？`
- 劳动仲裁时效是多久，从什么时候开始算 → `1.3.2 时效`
- 超过仲裁时效怎么办 → `6.3 超过仲裁时效怎么办`

真实路由验证中，问题“劳动合同法对未签订书面劳动合同怎么规定，申请仲裁要带什么？”没有出现“办事指南”字样，最终来源同时包含《劳动合同法》第八十二条和指南 `3.1 必备材料`、`5.2 申请劳动仲裁需要准备哪些证据？`。性能统计显示 `rewrite` 为 1 次、总模型调用为 2 次（改写和最终回答各一次），没有新增路由调用。

真实混合问题“劳动合同法对未签订书面劳动合同怎么规定？办事指南建议准备什么材料？”已通过端到端验证：Rerank 结果同时保留 `第十条`、`第八十二条` 等法条和指南 `6.2 未签订书面劳动合同`，回答分别给出书面合同规则与材料建议。
