# V12：按账号资料集合检索

demo_ab 可访问 A/B，demo_c 可访问 C，demo_abc 可访问 A/B/C。A 是劳动法，B 是劳动合同法，C 是调解仲裁法和仲裁指南。账号等级对应明确集合，不按数值大小自动继承，也不自动授予管理员权限。

网页每次提问由 web_app.py 从已认证用户 ID 调用 PostgresAccountStore.allowed_knowledge_bases。权限只来源于服务器数据库，问题内容或 JSON 中的范围不构成授权。没有可访问库返回 403；读取或校验权限失败返回 503，均不启动模型或保存半次问答。

rag_app.py 的候选检索将原有法律 / 法条 / 指南条件与 knowledge_base_id 的允许集合取交集。Chroma 和 BM25 使用同一条件；METADATA_FILTER=false 仅关闭问题路由，不关闭权限。空范围不做查询向量计算。BM25 本地索引包含整个当前资料集，但按范围筛选后才评分与返回候选。

web_rag.py 在远程重排前检查 active 状态和所属库，给重排器独立副本；重排后再次核对正文和元数据是否来自允许候选，允许新增 rerank_score。只有核验后的片段可以进入回答上下文和引用。没有可用依据直接返回“当前账号可访问的资料中没有足够依据。”，跳过回答模型；非空范围的问题改写 / 向量查询可能已执行。

query_rewrite.py 只向模型发送允许库的指南目录。网页改写保留近期用户问题，不重新发送历史助手回答，避免旧回答包含的此前可见资料再次进入模型。数据库历史和网页历史展示保持原样；这不是旧答案清除机制，跟进问题涉及只在旧回答中出现的指代时可能需要用户补充。

产品 create_web_rag_turn 要求范围，漏传即拒绝；原 CLI 教学和显式注入的测试 / 调试工厂保持原接口，不作为公开匿名问答入口。每轮使用请求开始时读取的权限快照，下一轮反映权限调整；不宣称在途即时撤销。管理员操作界面、远程独立网关、阶段 / 召回正文日志、持久图状态及恢复等仍按后续计划处理。

验收重点是“引用来自账号允许的资料”，不是“模型知道哪些法规”。分别在 demo_ab 和 demo_c 的新对话询问劳动合同法第二十条，检查后者不会引用 B 库资料；也可以用仲裁指南反向核验 C 库范围。相似问题可能在其他允许法规中找到相关依据，因此不能只凭回答措辞判断权限。

代理验证：261 项完整 Python 测试（RUN_POSTGRES_TESTS=1）与 10 项 Node 测试通过。独立只读审查无阻塞问题，并独立复跑 13 项权限测试。真实 public 三个账号和现有 legal_8503b0681f30236940374269 索引通过 15 组只读检查：向量 / 混合、路由开 / 关均受集合约束；明确 B 库第二十条，demo_ab / demo_abc 得到 1 条，demo_c 得到 0 条。复用已有向量，远程模型调用为 0。用户网页权限验收与实现理解尚待确认。
